* Repository contents

Entries are separated by class, each in its own directory. Entries are
divided in small files, so that they can be previewed on GitHub and
processed in less powerful computers. The repository structure is
meant for development: if you would like a copy of the data, you
should go to our [[https://github.com/LFG-PTBR/MorphoBr/releases][releases page]].

Each file holds the lemmas whose first letter (without accents) is the
one in the file name. Lines are kept in a canonical order: sorted by
analysis and then by form, comparing bytes (=LC_ALL=C=), without
repeated lines, so all entries of a lemma stay together. After editing
a dictionary, run =tools/canonicalize.sh= (or =tools/canonicalize.sh
--check= to only check the order).

Code (and its documentation) employed in the resource's development
can be found in the =tools/= directory.

* Inflection rules and full-form lists

Regular paradigms are generated by finite-state rules instead of being
listed form by form (see issue #143):

- =rules/verbs.lexc= defines the inflection classes, each named after
  a model verb (=ABAFAR= for regular verbs in /-ar/, =PASSEAR= for
  verbs in /-ear/, =BATER= for /-er/, =PARTIR= for /-ir/, and classes
  such as =ATRIBUIR= (/-uir/), =ADERIR= (/-erir/, /adiro/), =CONDUZIR=,
  =FAZER= or =CONTER= for verbs that share an ending), and
  =rules/orthography.foma= the spelling alternations (/ficar/ →
  /fique/, /pagar/ → /pague/, /abraçar/ → /abrace/; /conhecer/ →
  /conheço/, /proteger/ → /protejo/, /distinguir/ → /distingo/).
- =rules/classes.tsv= registers, for each class, the model verb, the
  ending removed to get the stem (/aderir/ → /ad-/, so /preferir/ →
  /pref-/ + /-iro/) and the suffix of the lemmas it applies to. A new
  class is created from the forms of its model with
  =tools/make-class.py MODEL ENDING=.
- =lexicon/verbs/<model>.tsv= lists, one per line, the lemmas that
  inflect like the model verb (e.g. =lexicon/verbs/abafar.tsv=).
- The =*.dict= files keep the entries that the rules do not generate:
  irregular verbs, variants, homographs and words of other classes.

The compiled transducer is the union of both, so the rules never change
the content of the lexicon. A lemma is moved to the rules only if they
generate nothing that was not in the =*.dict= files; then exactly the
generated pairs are removed from them. =tools/rules-migrate.py= does
this, trying for each lemma the classes that match its ending from the
most specific to the most general (it can be run again after a new
class is added); since only lemmas that pass are moved, a new class
never changes the lexicon, even if its model is badly chosen. And
=tools/expand.sh= writes the complete full-form list (rules +
=*.dict=, in canonical order). To check that a change in the rules or
in the lists preserves the lexicon, run it before and after the change
and compare the outputs:

#+begin_src bash
    % tools/expand.sh > before.txt      # on the original revision
    % tools/expand.sh > after.txt       # with the change
    % cmp before.txt after.txt
#+end_src

* Tagset

The tagset used in the above projects was converted to a more
mnemonical one which generally follows the notational conventions of
the descriptive linguistic and finite-state morphology literatures,
see the =TAGSET= file.

* Morphological analysis

In order to use MorphoBr resources for morphological analysis in the
context of syntactic parsing (e.g. with PorGram), they must be
compiled into finite-state transducers. The easier way is to load and
compile it with [[http://fomafst.github.io][Foma]]:

#+begin_src bash
    % ./compile.sh
    % echo "fortinho" | flookup -i morphobr.bin
    fortinho	forte+N+DIM+M+SG
    fortinho	forte+A+DIM+M+SG

    % echo "comprei-o" | flookup -i morphobr.bin
    comprei-o	comprar+V.ele.ACC.3.M.SG+PRF+1+SG

#+end_src

=compile.sh= builds the converter in =code/= with [[https://docs.haskellstack.org][stack]], converts the
dictionaries to Foma's spaced-text format and runs =compile.foma=,
producing =morphobr.bin=. The build takes about 2 minutes and needs
about 5 GB of memory.

For that, you need:

1. [[https://docs.haskellstack.org][stack]], to build the converter in =code/=.

2. A Foma that can read the large lexicon. Foma 0.10.0 (e.g. from
   Homebrew) aborts with =Stack full!= because its internal stacks
   have a fixed size. Use Foma with dynamic stacks
   ([[https://github.com/mhulden/foma/pull/176][mhulden/foma#176]]),
   or change the =MAX_STACK= value in =foma/int_stack.c= to at least
   9097152 and compile Foma. To use a Foma that is not in the =PATH=,
   set =FOMA=:

   #+begin_src bash
    % FOMA=~/foma/foma/build/foma ./compile.sh
   #+end_src

See https://github.com/mhulden/foma/issues/130.

The dictionary files must use LF line endings (enforced by
=.gitattributes=): CR characters break the compilation.

Python modules as well as XFST and bash scripts for performing this
task are available in the =tools/= folder. Inadequacies and errors
found in the source dictionaries were corrected using these tools. See
the respective incode documentation for a detailed description of the
changes made to the source entries.
